# 手写 Jacobian 替换验证

## 结论先行

本次把当前优化链路里的数值/有限差分 Jacobian 换成手写解析 Jacobian 后，`test_math` 的有限差分对照通过，仿真系统 `two_cams_two_imus` 也能正常收敛。和替换前相比，当前手写版本在同一组限制参数下 final cost 从 `7767.578` 降到 `7757.166`，solver total time 从 `20.552 s` 降到 `2.634 s`，约 `7.80x` 更快。

精度层面没有出现系统性退化。重投影 RMS 高 `0.00098 px`，gyro RMS 高 `3.6e-5 rad/s`，accel RMS 低 `1.1e-5 m/s^2`；camera rotation error 更低，camera translation error 从约 `0.16 um` 到约 `0.92 um`，仍处在很小量级。这个实验能证明这次替换在当前仿真场景和触发配置下正确且明显提速，但不能替代全数据集、多次重复 benchmark。

## 背景

代码里原先有三类优化时 Jacobian 不是手写解析形式：

| 类别 | 原实现 | 当前实现 | 触发条件 |
|---|---|---|---|
| camera-chain 外参先验 | `ceres::NumericDiffCostFunction` | `CameraChainExtrinsicPriorCost` 手写 `Evaluate()` 和 Jacobian | `--fix-camera-chain-extrinsics` |
| `Pose6Manifold` | `PlusJacobian()` / `MinusJacobian()` 内部有限差分 | 解析 `J_l(-r)^{-1}` 和 `C(r)J_l(r)` | `--extrinsic-manifold` 或 `--pose-control-manifold` |
| IMU time offset residual | gyro/accel time-offset block 内部有限差分 | gyro/accel 解析时间导数 Jacobian | `--optimize-imu-time-offsets` |

其中 IMU time offset 的数学形式书里已经有：第 8 章 8.3.2、8.3.3 和附录 C 的 C.5、C.6。缺少的是当前 Ceres 的 camera-chain 外参先验和 `Pose6Manifold` raw Jacobian，因此本次补充了：

| 文档 | 新增内容 |
|---|---|
| `docs/books/kalibr_cam_imu_from_equations_to_ceres/00_符号表与约定.md` | 0.10.4 当前 Ceres `Pose6Manifold` 的 raw Plus/Minus Jacobian |
| `docs/books/kalibr_cam_imu_from_equations_to_ceres/08_时间偏移与外参.md` | 8.6.2 当前 Ceres 的 camera-chain 外参先验 Jacobian |
| `docs/books/kalibr_cam_imu_from_equations_to_ceres/appendix_C_Jacobian速查表.md` | C.4.1 camera-chain 外参先验速查表，C.13 `Pose6Manifold` raw Jacobian |

## 对比目标

这次实验回答三个问题：

1. 手写 Jacobian 是否和有限差分数值 Jacobian 一致。
2. 替换后同一仿真任务是否还能收敛到同等精度。
3. 替换后优化效率收益有多大。

## 指标口径

| 指标 | 单位 | 越小/越大越好 | 含义 | 注意事项 |
|---|---|---|---|---|
| finite-difference check | pass/fail | pass 更好 | 解析 Jacobian 与中心差分的最大误差是否在阈值内 | 只覆盖构造的局部样例 |
| final cost | Ceres cost | 越小越好 | Ceres 终止时目标函数值 | 同一 problem size 下可比 |
| solver total time | s | 越小越好 | Ceres summary 的总耗时 | 比 `/usr/bin/time` 更聚焦 solver |
| real time | s | 越小越好 | `/usr/bin/time -p` 的 wall time | 包含加载、输出等外围开销 |
| residual RMS | px / rad/s / m/s^2 | 越小越好 | 输出 YAML 中各类 residual RMS | 不同残差类型不能跨单位比较 |
| extrinsic error | deg / m | 越小越好 | 和仿真 ground truth 比较 | camera chain 被强先验约束，translation error 很小 |
| time offset error | s | 越小越好 | 估计时间偏移与 ground truth 差值 | 本场景 ground truth 为 0 |

## 正确性验证

| 验证项 | 覆盖内容 | 命令 | 结果 |
|---|---|---|---|
| 单元测试 | `Pose6Manifold` Plus/Minus、camera-chain prior、gyro/accel time-offset residual | `cmake --build build --target test_math`；`./build/test_math` | pass |
| 应用构建 | 当前 calibration app | `cmake --build build --target calibrate_cam_imu` | pass |

新增 `test_math` 检查覆盖三类替换路径：`Pose6Manifold` 直接对 `Plus()` 和 `Minus()` 做中心差分；camera-chain prior 通过 `ceres::Problem::Evaluate()` 取 CRS Jacobian 后逐参数块差分；gyro/accel time-offset residual 直接用 `CostFunction::Evaluate()` 对所有参数块做中心差分。当前阈值能覆盖 `rotationMatrixToVector` 在近零处的数值阈值影响。

## 结果总览

| 场景 | 配置 | final cost | solver total time | real time | 结论 |
|---|---|---:|---:|---:|---|
| baseline | 数值/有限差分 Jacobian | `7767.578` | `20.552 s` | `24.39 s` | 能收敛，但 Jacobian 计算很慢 |
| current | 手写解析 Jacobian | `7757.166` | `2.634 s` | `3.77 s` | 精度同量级，solver 约 `7.80x` 更快 |

当前版本 problem size 和 baseline 完全一致：`residual_blocks=40211`，`scalar_residuals=138272`，`parameter_blocks=3081`，`active_parameter_blocks=3080`，`tangent_params=12305`。因此这组耗时差异主要来自 Jacobian 计算方式变化，而不是问题规模变化。

## 仿真结果

### 效率

| 指标 | baseline | current | current 相对 baseline |
|---|---:|---:|---:|
| `/usr/bin/time` real | `24.39 s` | `3.77 s` | `6.47x` 更快 |
| `/usr/bin/time` user | `64.14 s` | `3.50 s` | `18.33x` 更少 CPU time |
| `/usr/bin/time` sys | `0.61 s` | `0.10 s` | `6.10x` 更少 sys time |
| Ceres total time | `20.5519 s` | `2.6338 s` | `7.80x` 更快 |
| Ceres minimizer time | `20.3534 s` | `2.5921 s` | `7.85x` 更快 |
| iterations | `9` | `9` | 相同 |
| successful / unsuccessful steps | `3 / 6` | `3 / 6` | 相同 |

效率收益非常明确。三类替换里 IMU time-offset residual 的收益最大，因为有限差分会在大量 IMU residual 上重复调用完整 residual evaluation；camera-chain prior 数量只有 1 个，主要收益是去掉数值差分和减少不确定性；`Pose6Manifold` 的收益体现在每次 Ceres 需要 manifold Jacobian 时不再做差分。

### 优化残差

| 指标 | baseline | current | delta |
|---|---:|---:|---:|
| initial cost | `13043.86` | `13043.86` | `0` |
| final cost | `7767.578` | `7757.166` | `-10.412` |
| reprojection RMS | `0.265427 px` | `0.266404 px` | `+0.000977 px` |
| gyro RMS | `0.0157331 rad/s` | `0.0157686 rad/s` | `+0.0000355 rad/s` |
| accel RMS | `0.156786 m/s^2` | `0.156775 m/s^2` | `-0.0000114 m/s^2` |

final cost 当前更低，但各类 residual RMS 变化都很小。因为优化是非线性问题，Jacobian 更准确后走到略不同的局部位置是正常现象；这里没有看到某类 residual 明显恶化。

构建 baseline：


## 结论

这次替换可以保留。解析 Jacobian 已通过局部有限差分检查，并在同时触发 camera-chain prior、IMU time offset 和 pose manifold 的仿真任务中保持同等精度，效率收益明显。当前证据最强的结论是：在 `two_cams_two_imus` 快速 benchmark 配置下，手写 Jacobian 没有引入可见精度回退，并把 solver 时间降低到原来的约 `12.8%`。
