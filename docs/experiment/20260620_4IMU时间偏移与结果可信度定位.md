# 4IMU 时间偏移与结果可信度定位

## 背景

生产数据里的 4 路 IMU 与 camera 不是同一个时间相位。`2025_03_14_00_34_14` 上，4 次 `1cam+1imu` 的 time shift 分别接近 `-120ms / -102ms / -21ms / -0.5ms`。如果 4IMU joint 只保留一个 camera-to-reference-IMU time shift，优化器必须用相机外参、IMU chain 外参、bias/pose spline 去吸收剩余时间误差，`cam0` 平移和 IMU residual 都会被带偏。

这次验证的目标是把 Ceres 多 IMU 也接上 IMU delay correction，并把它设为多 IMU 默认行为；同时确认它和 Kalibr 的 `--imu-delay-by-correlation` 在语义上是否一致。

## 实验问题

1. Kalibr 的 IMU delay 是什么；不开启时是否已经存在每路 IMU 独立 time offset。
2. Ceres 多 IMU 应不应该默认启用 delay correction。
3. Ceres 加入 delay correction 后，在至少 4 个生产 session 上，`1cam+1imu / 1cam+2imu / 1cam+4imu` 的时间、精度、设计变量和 residual 是否稳定。
4. `cam0` 平移和 time shift 谁更可信，哪些现象属于 delay 问题，哪些仍是 Ceres 外参/停止准则问题。

## 模型结论

Kalibr 的 `--imu-delay-by-correlation` 不是把每路 IMU time offset 作为连续设计变量一起优化，而是在多 IMU 初始化阶段用 gyro correlation 估出非参考 IMU 相对 IMU0 的时间偏移，并在构造多 IMU residual 时使用这些偏移。输出里的 `time offset with respect to IMU0` 应按下面方式组合：

```text
T_cam_imui = T_cam_imu0 * inverse(T_i_b)
timeshift(cam to imui) = timeshift(cam to imu0) - time_offset_i
```

不开启 `--imu-delay-by-correlation` 时，Kalibr 的多 IMU 结果文件仍会有每路 IMU 的 `time offset with respect to IMU0` 字段，但默认是 `0`。这不是“初值离最优点太远导致没优化回来”，而是模型口径里 non-reference IMU 的相对 delay 没有被估计出来。

023e1e6 版本的 Ceres 对齐同样的固定 correction 语义：`camera_time_shift_s` 仍是优化变量；`imu_time_offsets_s` 是多 IMU 的固定时间轴修正常量，默认由 gyro correlation 初始化，不作为 Ceres design variable，不新增 residual。multi-IMU residual 和 residual statistics 都用 `sample.timestamp_s + imu_time_offsets_s[i]` 查询 pose/bias spline。

2026-06-21 的后续实现把这一步又向前推进：gyro correlation 仍负责给非参考 IMU offset 初值，但 `imu_time_offsets_s[1..N-1]` 在多 IMU、`calibrated` IMU 模型下默认作为 Ceres 变量进入同一个 problem，并用 `--fix-imu-time-offsets` 保留 023e1e6 的固定 correction 口径。

Ceres 多 IMU 求解不是默认多 stage。默认是把 camera residual、每路 IMU gyro/accel residual、pose/bias prior、time prior、gravity tangent、IMU chain extrinsic 和可选 per-IMU time offset 等放进同一个 Ceres problem 联合优化；`--optimizer-stages` 只是可选的 staged 求解包装。IMU chain prior 和 delay correction 属于 solve 前的初始化/修正。

## cam0 平移判断

这里的 `cam0 平移` 指 Ceres YAML 里的 `camera_to_body.T_c_b` 或 Kalibr 结果里的 `T_ci` 的平移部分，本质是 cam0 相对参考 IMU/body 的平移。它不是每路 IMU 都独立的一组相机平移；多 IMU joint 里其他 IMU 的 camera-to-IMU 平移要通过 `T_cam_imu0 * inverse(T_i_b)` 组合出来。

本次结果里，Ceres delay 4IMU 的 time shift 和 IMU residual 已经明显正确，但 `T_c_b` 平移还没有达到 Kalibr delay 的可信程度。`2025_03_14_00_34_14` 在 023e1e6 固定 correction 口径下的 Ceres 4IMU `T_c_b` 平移是 `[0.0693, 0.1109, 0.0030]m`，组合回 imu0 时相对单 IMU 仍有约 `79mm` 差；但非参考 IMU 的平移差约 `12.8mm / 18.2mm / 12.0mm`。这说明 delay correction 解决了时间相位问题，但没有完全解决 Ceres 的 reference IMU camera translation 问题。

补跑了一次高精度 sanity check：去掉 `--estimate-camera-translation-prior`，设置 `--max-iterations 150 --solver-absolute-parameter-tolerance -1`。该 run 用时 `891.7s`，最后 `NO_CONVERGENCE`，`T_c_b` 漂到接近零，residual 也变差：reproj `0.2172px`、gyro `0.0176rad/s`、accel `0.1584m/s^2`。这不是更可信解，反而说明多 IMU translation 仍受初始化、先验和停止口径强影响。

因此当前可信度排序是：

1. Kalibr delay 4IMU：最可信，time、residual、平移都贴近 4 次单 IMU。
2. Ceres delay 4IMU：time 和 residual 已经对齐，速度明显更快；平移还需要继续定位。
3. Kalibr 默认 4IMU / Ceres 无 delay：对这类数据不应作为真值，因为 non-reference IMU delay 被固定为 0。

## 结论

Ceres 应该默认启用 IMU delay correction，但只在多 IMU 场景启用。这个默认是必要的：生产数据里不同 IMU 的相对 delay 可达 `20ms` 到 `126ms`，不建模会让 joint 标定求解错误问题。

本次实验先证明“固定 correction 常量”是合理的第一步，因为它与 Kalibr `--imu-delay-by-correlation` 语义一致，且 4 个生产 session 已验证 effective time shift 平均差约 `1ms`。2026-06-21 的后续实现已经把 per-IMU delay 升级为小范围优化变量，默认仍依赖 correlation 初值和 box bound 控制风险。

仍未解决的问题是 Ceres 多 IMU 的 `cam0`/reference IMU 平移。delay correction 不是这个问题的全部根因；后续应单独定位 camera translation prior、IMU chain lever prior、gauge/可观性、stopping criteria 对 `T_c_b` 的影响。
