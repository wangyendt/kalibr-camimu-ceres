# 多 IMU 输入支持验证

## 背景

第 13 章把多相机 / 多 IMU 的实现边界说清楚了：所有传感器共享同一条 body trajectory，camera 和 IMU 的私有变量按 index 分开。当前仓库原本已有多相机 joint 入口，但 IMU 只有一组 `--imu`、`--imu-data`、bias spline、外参和扩展内参。本次记录先保留多 IMU 输入和因子图接线的 smoke 证据；后续 Kalibr 热启动 benchmark 对齐结论见 `20260616_Ceres与KalibrDocker多数据集速度精度对比.md` 和 `docs/knowhow/20260619_Kalibr_IRLS鲁棒核对齐.md`。

## 实验问题

1. `calibrate_cam_imu` 是否支持重复传入 `--imu` 和 `--imu-data`。
2. 多 IMU 是否为每个 IMU 建立独立 bias、外参和 IMU intrinsics，同时共享 pose spline 和 gravity。
3. 旧的 TUM 双 camera 单 IMU 路径是否没有被多 IMU 改动破坏。

## 假设

多 IMU 不需要修改单条 gyro / accel residual 的物理公式，只需要把 residual 连接到当前 IMU 的私有 block。第 0 个 IMU 仍作为 reference IMU，默认固定 `T_i_b`；后续 IMU 的 `T_i_b` 和 lever arm 参与优化。

## 分析

当前实现的核心行为符合第 13 章的因子图结构：多组 IMU residual 共享 pose spline 和 gravity，但各自连接不同的 IMU 外参、bias controls 和 IMU intrinsics。第 0 个 IMU 的外参保持 reference 固定；非 reference IMU 的外参进入 active parameter blocks。

benchmark smoke 的非 reference IMU lever arm 在 1 次迭代、小数据规模、零初值下不稳定。这不是建图失败，而是初始化和收敛问题：benchmark fixture YAML 没有提供 IMU 间外参初值。后续已经补充从 Kalibr multi-IMU joint result 热启动 `imu_chain`，并进一步定位到 Kalibr IRLS M-estimator 与 Ceres 标准 robust loss 的线性化差异。

TUM 双 camera dry-run 确认现有多相机路径仍可用。本轮没有重新跑完整 TUM benchmark；它只作为多 camera smoke，证明多 IMU 改动没有破坏 shared camchain + repeated `--corners` 的建图入口。

## 结论

当前仓库已经支持多 IMU joint 建图和求解入口：

- `--imu` 可重复，`--imu-data` 可重复，二者数量必须一致。
- 第一个 IMU 是 reference IMU，默认固定外参。
- 每个 IMU 有独立 bias controls、外参和扩展 IMU intrinsics。
- 残差统计聚合所有 IMU，结果 YAML 会额外输出 `imu_chain`。

本记录的原始结论只覆盖建图 smoke。后续验证已在 Kalibr 热启动 benchmark 口径下通过：Ceres staged `pbg,pbegt` 可释放 camera/time，reprojection mean `0.229823 px`，camera 差 `0.004655 deg / 0.0755 mm`，time-shift 差 `0.4727 ms`。

## 未覆盖问题

- 多 IMU 冷启动全自由精度仍未证明；当前已证明的是 Kalibr 热启动 benchmark 口径。
- `--staged` 已接入 multi-IMU benchmark 路径；更复杂的多 camera + 多 IMU staged 组合还需要单独全量验证。
- `--export-imu-diagnostics` 仍按 reference IMU 输出，尚未扩展为每个 IMU 一个文件。
- 多 IMU time offset 还未作为独立变量实现；当前所有 IMU 样本按 CSV 时间戳直接查询同一条 pose spline。

## 下一步

下一步如果要推进冷启动能力，需要补非 reference IMU 的 gyro-correlation rotation/time 初值，或引入可配置的 IMU chain prior；当前文档不把热启动 benchmark 结论外推到冷启动全自由。
